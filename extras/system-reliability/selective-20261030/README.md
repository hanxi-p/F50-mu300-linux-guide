# F50 旧版后台组件增量维护（2026-10-30）

本目录保存针对已安装旧版 F50 厂商5.4环境适配的五个源码快照、增量补丁及校验清单。参考上游 mu300-linux [v2026.10.29.1](https://github.com/dikeckaan/mu300-linux/releases/tag/v2026.10.29.1) 的 [PR435](https://github.com/dikeckaan/mu300-linux/pull/435) 和 [PR439](https://github.com/dikeckaan/mu300-linux/pull/439)。原有上游代码保留MIT许可，见LICENSE。

## 内容与适用条件

- 按键：tick先判断LED是否到期；TERM清理自身key reader和循环进程，原按键动作保持。
- LED：配置与uptime用内建read，保留默认常亮、灯色、亮度和超时。
- 热保护：普通采样减少辅助进程，无有效SoC温度时保留限制与告警；阈值、5秒周期、厂商trip优先及F50忽略虚假电池温度的行为保持。
- 启动日志：限定读取量，前90秒仍2秒一轮，后续30秒一轮；下次自然开机使用。
- 升级前：核对kernel.release、预期模块名、数量与非空，再sync；下次内核升级使用。

这里只移植PR439的模块完整性前置检查，**没有配套modules.pending启动恢复，不能保证升级断电自动恢复**。新版整套电源、CPU、USB与启动组件没有随此目录引入；本次也不更新内核、驱动、rootfs、网络、登录或前端。

BASE_SHA256SUMS记录适配前设备五个脚本的精确摘要，RESULT_SHA256SUMS记录本次结果。先识别机型、内核、现有定制和启动入口，再核对BASE；若已匹配RESULT则不重复替换。任一旧文件不匹配时停止并重新审阅差异，不能仅凭版本号覆盖。其他路由器和新版完整rootfs不属于此次验证范围。

## 文件与维护方法

- files/：五个已验证源码快照，安装目标均在/opt/mu300/bin/。
- selective.patch：原五文件到结果的统一补丁；处理时保持LF，Windows使用git -c core.autocrlf=false apply。
- SHA256SUMS：本目录公开文件摘要；在本目录执行sha256sum -c SHA256SUMS检查分发内容。
- BASE_SHA256SUMS / RESULT_SHA256SUMS：在设备执行sha256sum -c对应文件，核对安装前或安装后实际文件；它们不修改设备。
- tests/isolation.sh：假sysfs、假按键和假模块包三轮回归，不执行真实关机或刷写。需在隔离测试机准备/tmp/f50-selective-check-20261030/candidate/并放入files/内五个脚本，再运行测试；测试目录不要混放其他文件。

本目录没有自动安装器，不由上一级旧版install.sh自动覆盖。维护时先备份原五文件、相关启动定义、配置和有效历史，保存运行实例与文件摘要；全部候选语法与SHA检查完成后，将候选权限设为755，再用完整文件rename替换。只重载按键服务及procd中的thermalguard实例，不重启整个mu300-post，以免触发USB/蜂窝/Wi-Fi动作；旧按键pipeline须按原PID及启动时间清理遗留的直接子进程。记录设备实际的恢复命令，不把其他机型的服务名照搬。

复核AP、统计刷新、计数不回退、配置/页面/模块摘要、boot-id及其他服务实例状态。启动recorder和真实内核升级未通过实际运行测试；回退工具保存及语法检查不等于现场回退演练。

## 已完成与未完成

五脚本语法、三轮共84项隔离断言、补丁重放及活动文件摘要检查已完成。测试覆盖超时/无效deadline、无效tick、原按键分支、TERM清理、厂商trip只观察、虚假电池、温度失读，以及模块空/缺失/错名/多余/空版本拒绝。

正式维护只重载两个后台实例，检查管理/AP和有效计数保持。短时错误日志观察不代表长期驱动稳定性，也没有据此宣称整机CPU降幅。私有配置、名单、历史、原始日志和整机备份不在本目录发布。
