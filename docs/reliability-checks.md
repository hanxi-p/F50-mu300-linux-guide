# 稳定性检查与复刻验收

本页用于安装后核对，以及第十一、十二章扩展的最终验收。基础系统固定为 v2026.10.11；系统组件修补、首页扩展、短信邮件分别记录版本，不用一个启动组件版本代表整个系统。

## 按顺序部署

1. 前十章：准备 → 原始备份 → B09 → 解锁 → Root → SD 安装 → 管理配置与切换。
2. [安装后优化](10a-post-install-optimization.md)：核对并部署 [系统组件修补](../extras/system-reliability/README.md)，再完成密码、SSH、无线、时间、软件源与备份。
3. 按需部署 [首页扩展](11-optional-dashboard.md) 或 [短信邮件](12-optional-features.md)，核对各自依赖、哈希与恢复入口。
4. 重新检查管理与联网，保存包含新增配置的私人备份。

用户需要自己的 SIM、SD、密码及 SMTP / 代理配置；这些内容不在公共配套文件中。需要插拔、短接、WebUSB 设备选择或本地输入密码时，由 Codex 给出当前步骤并等待完成，其他步骤按实际检测结果推进。

## 锁与退出路径

| 路径 | 处理方式 | 验收依据 |
| --- | --- | --- |
| 频段 apply 锁与 radio 锁 | 开机早期回放使用非阻塞 apply 锁，忙时延期；页面设置按原流程等待 radio | 模拟 apply 锁被持有，早期回放立即返回且不写 AT、不创建完成标记 |
| CPU / 插件目录锁 | PID 与进程开始时间识别持有者；活锁保留，死亡持有者立即回收 | 活锁互斥与未来时间戳的陈旧锁回收测试 |
| 无线 / DNS / 历史守护 | 跟踪分离任务，停止时清理子进程；procd 在退出后重启 | 挂起任务的停止清理、连续状态读取与服务状态检查 |
| 短信接收守护 / 短信池 | 内核 flock 单实例；同步批次不继承守护锁；停止批次时清理子进程 | 双守护竞争、两个池写入者串行与取消后释放锁测试 |
| 启动选择与系统更新 | 共用 boot-control 锁；更新、回滚和清理串行；试启动设置失败拒绝写 boot | 锁竞争按期限退出；模拟试启动设置失败，不写启动镜像 |
| 邮件发送 | 持久队列、成功记录、漏入队补偿、逐条重试与单次超时 | 失败保留、重启续发、去重、取消清理和服务恢复测试 |

2026-10-10 已在现有 F50 完成上述逻辑测试，以及 IPv6 双前缀加入 / 撤回、DNS 链、Wi-Fi AP、蜂窝 carrier 和配套文件校验。公共 Markdown 本地链接及锚点、JavaScript 语法、设备端 shell 语法和 SHA256 均已核对。

服务恢复依据 OpenWrt 的 [procd 生命周期与 respawn 参数](https://openwrt.org/docs/guide-developer/procd-init-scripts)，设备总看门狗与进程恢复的职责见 [硬件 watchdog](https://openwrt.org/docs/guide-user/hardware/watchdog)。进程超时可以清理用户态任务；内核不可中断等待、供电或 SD 硬件故障需要另查驱动日志与硬件，不能用 shell 超时当作已修复。

## 自己的设备怎样验收

- 保留 USB，确认 SSH、LuCI、手机 Wi-Fi 连接及蜂窝 DNS / 小规模外网请求。
- 核对基础系统、组件与脚本哈希；未部署的可选项不勾选为完成。
- 连续读取后台状态，曲线保留最近五分钟，关闭网页后仍由后台采集。
- 需要插件时，分别切换 OpenClash / AdGuard Home，并检查每种启停组合的 DNS；完整测试需使用自己的配置。
- 短信转发先检查测试邮件的主题、发送号码与原文，再用一条真实新短信核对收件端。
- 新设备交付前做一次重启和冷启动验收；管理连通、SD 根挂载和启动确认都正常再勾选。现有设备本轮逻辑检查没有重复执行降级或断电恢复。
- 备份双端哈希、关键文件与加密归档测试通过；恢复演练是单独步骤，不能用“压缩包可打开”代替。

## 已核对的流程细节

- 电脑的 Wi-Fi metric 属于网卡，不属于 SSID。只在连接 F50 时临时调整，离开 F50 后恢复；专用 USB 管理租约不接收默认网关和 DNS。
- 首页依赖包括 `vnstat2`、`flock` 和 `curl`；短信转发还需 `msmtp`。准备缺少的软件由 Codex 完成。
- 5.4 的 flowtable 修补与关闭流量卸载配套使用，保持管理和 NAT 可用。
- 备份排除主系统与 Android 容器的运行时绑定挂载，保留 SD 持久文件、启动链和本机分区恢复数据。
- 多个功能共用 `f50-bounded`。恢复某个扩展时保留当前共用执行器，避免回退或删除它影响其他功能。
- SMTP 接受与最终收件分别确认；成功应答丢失时可能重复投递，用固定 Message-ID / 短信 ID 识别。
