# 更新前后的风险清单

这是持续维护的回归清单。每次更新先检查可能失去 Wi-Fi 管理、卡住控制任务或损坏启动的数据路径，再检查功能与界面。新增故障、复现条件或代码风险必须追加到这里；已有项目保留编号，不因一次测试通过而删除。

状态分为：**已修补并测试**、**已有防护需回归**、**待核实**。测试通过只代表记录的条件；未执行的项目写“未测”，不能自动勾选。最近整理日期：2026-10-10（UTC+8）。

每次相关更新至少覆盖：正常信号、模拟 AT 无响应、控制任务忙、DNS 服务异常四种条件。真实弱信号或无信号测试必须记录实际信号、注册状态和持续时间，不能用普通联网测试代替。Wi-Fi 手机端与 USB 检查分别记录，缺少手机测试时注明“未测”。

1. 更新前读取本清单与最近回归记录，保存版本、运行状态和可恢复的原文件。按改动标出受影响的风险编号。
2. 所有更新先执行 P0 的非破坏性基础检查：SSH/网页/AP、DNS、关键服务、锁与残留进程、资源和内核日志。没有安全测试条件时记录“未测”和原因。
3. 检查实际改动路径的失败分支：超时、通道忙、查询失败、子进程退出、并发及取消。优先使用隔离 fixture；真实服务操作恢复到测试前状态。
4. 涉及网络/服务控制时测试 4G/自动 5G 往返、DNS 四组合与模式切换。涉及 Wi-Fi 时检查非 DFS、国家码、手动关闭保护、pending 边界及实际手机访问。启动/换卡测试需要相应设备操作条件，不能冒充已完成。
5. 复查 P1/P2 中受影响项目；记录“通过/失败/未测/不适用”、时间、证据路径、版本与回退入口。新风险立即新增编号，记录复现步骤、影响、修补和测试方法。
6. 修复后重跑失败项及相邻共享资源路径。发布前核对设备、源码、配套安装文件与校验值一致；有失败项不得宣称整体检查通过，需明确剩余项。
