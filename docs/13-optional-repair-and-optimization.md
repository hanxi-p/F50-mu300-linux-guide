# 第十三章（可选）：故障修复与优化

让热点、后台和网络控制在插件切换、蜂窝重新注册时保持可管理，是本章的目标。这里汇总实际遇到的问题、对应措施及验收方法；配套文件由第十一章安装入口交付，不需要重新降级、解锁或刷写启动分区。

## 13.1 复制给 Codex

```text
请维护这台已安装 mu300-linux 的 F50。先读第十三章、docs/risk-register.md、docs/fix-history.md 和最新公开回归摘要。记录系统、内核、安装组件版本、热点、DNS、插件与性能模式初始状态。
按 P0 → 受影响 P1/P2 的顺序检查，保持 Wi-Fi 管理。先判断是否适用配套版本，再保存原文件及恢复方法，不直接全量升级系统库，不重刷启动分区，不清空流量记录。
对每项执行三层检查：明显错误与部署一致性；锁顺序、并发、超时和恢复逻辑；正常、失败、边界及重复操作测试。真实可逆开关至少三轮往返，测试后恢复初始状态。没有手机、冷启动或弱信号条件时写明未测，不把 USB 正常当成手机 Wi-Fi 通过。
如需安装首页及已配套的修补，按第十一章的下载、SHA256、版本检查、备份和安装步骤执行。高级 rpcd 库修补及无线命令追踪先阅读本章边界，不能当通用补丁自动套用。
保存每轮证据，新问题追加风险编号和修复历史；修补后重测失败项及相关功能。交付已修复项、未解决项、原状态恢复结果与备份位置。
```

## 13.2 我们遇到哪些问题，怎么处理

| 问题 | 原因或排查方向 | 修补与优化措施 | 如何验收 |
|---|---|---|---|
| 手机无法加入热点，后台却显示 AP 正常 | 零 MAC / BSSID；关联、DHCP 与网页可达是不同环节 | 使用有效单播 MAC；启动检查 BSSID、carrier 和 pending；保留用户主动关闭状态 | 手机重新加入、取得地址并打开管理 IP；冷启动另外验收 |
| 5GHz 热点迟迟不出现 | DFS 等待或地区与信道组合不合法 | 按当前国家码与无线能力选择合法非 DFS 组；没有合法组合时明确报错 | 核对实际信道、hostapd 状态及手机连接，不固定猜测国家码 |
| 启动保护反复重配已经正常的热点 | 健康 AP 也走恢复流程 | 启动 hook 使用 `--if-needed`，四项健康条件同时满足时跳过；显式恢复入口保留 | 三轮健康调用 hostapd PID 不变；异常进入恢复路径，冷启动单列 |
| 首页出现了，数字和曲线很慢；出现 XHR 超时 | 首次慢请求拖住控制初始化；RPC 互相等待 | 后台持续采样、首屏缓存、状态与控制独立请求；每个控制请求设置期限 | 首次访问、刷新、请求挂起和迟到响应；缓存不得冒充实时状态 |
| OpenClash / AdGuard Home 长期停在开启或关闭中 | 防火墙回调等待子进程、共享锁状态误判、页面等待未解除 | 回调仅排队；独立 DNS 守护处理；有限服务操作、锁与子进程清理；页面失败后重新读取 | 三轮四组合、DNS、本地后台与恢复初始插件状态 |
| 插件切换后 DNS 暂时失效 | dnsmasq 重载返回不等于新端口已就绪 | 有限等待本地 DNS 端口；代理、过滤、直连链路分开检查；失败保留实际服务状态 | 每种插件组合查询本地 DNS，并核对公网访问；弱信号与公网故障分开记录 |
| 4G / 自动 5G 倒计时消失、失联时误显示切换中 | 刷新丢失操作起点，或没有区分 RPC 无响应和实际后台任务 | 点击立即执行；30 秒估计倒计时；就绪提前结束；会话保存已接受任务；无响应显示禁用状态 | 三轮往返及刷新、挂起、迟到、超时；以新鲜注册与数据连接判定完成 |
| 性能按钮可能无限等待 | 查询或写入请求没有独立截止时间 | get / set 各自限时；防重复；迟到查询不能继续提交写入 | 三轮模式往返，核心状态与 AP / HTTP 可用；故障夹具三轮 |
| 流量突然多出约 4.295 GB | 计数器下降被 vnStat 当作 32 位回绕 | 对固定构建应用下降返回零补丁；采样遇到缺失值跳过，保持下一次有效基线 | 下降、正常增长、合法大增量及不同间隔；切网前后核对 RX+TX |
| 今日 / 本月数值漏计，查询失败变成零 | 同周期重复记录被覆盖或只取一行；维护工具日期格式错误 | 周期记录求和；按 vnStat 日期格式写入；失败返回错误；归档校验整批再写 | 重复/反序记录、查询失败、小时边界、写盘失败；不再清空历史 |
| 登录页依赖错误 | `cbi.js` 未在构造 LuCI 前加载 | 在匹配 Aurora 模板中调整依赖顺序，仅加载一次 | 匿名与登录页面、模板幂等和主题；完整登录往返单列 |
| 修改了源码，实际首页仍加载旧版 | 首页 require 别名与通用文件不同，检查遗漏活动路径 | 按安装映射同步全部别名；检查 UTF-8、HTTP 返回及备份成员 | 设备、负载、实际 require 文件逐项 SHA256；浏览器真实操作后重新备份 |
| RPC 对象短暂消失 | 曾捕获 rpcd 崩溃；发现旧 libubox 存在回调删除 watcher 后访问风险 | 保存完整崩溃上下文；针对已核对 ABI 的 rpcd 单独加载回移修复库 | 原库/修复库隔离复现、导出符号、独立 rpcd、三轮插件组合；见下一节边界 |
| 错误日志不全或重启后丢失 | RAM 日志轮转，过滤遗漏寄存器与堆栈 | 独立 SD 日志服务，保留 30 天、总额 2 GiB、单文件轮转；内核故障保留后续上下文 | 过期、容量、权限、写入失败及三轮启停；日志不占网络控制锁 |

更多历史项目包括 AT FIFO 阻塞、更新/回滚互斥、IPv6 前缀学习、短信邮件重试和备份中断恢复，见 [持续风险清单](risk-register.md)、[修复历史](fix-history.md) 与 [第十二章](12-optional-features.md)。这些编号在修补后继续保留，供以后更新回归。

## 13.3 配套文件与适用范围

- [第十一章安装入口](11-optional-dashboard.md) 提供匹配 `v2026.10.11`、厂商 5.4 内核、Aurora / MU300 面板的负载、校验与恢复脚本。不同版本先比对，不直接套用。
- 流量、历史、控制期限、登录依赖、健康热点跳过及日志修补随 [dashboard 配套文件](../extras/dashboard/) 交付。更新不应清空用户统计、密码、订阅或邮箱配置。
- `f50-wifi-command-trace.uc` 是**诊断工具**：在匹配的 mac80211 ucode 脚本中记录失败的具体 PHY 命令，供定位 `-12` 使用。它不修复无线驱动，也不自动重启热点。先保存原脚本；不匹配即停止。当前设备已部署追踪，真实重新加载 / 冷启动未测，默认首页安装器不自动启用它。
- rpcd 私有库回移是**当前设备的定向修补**，不是通用系统升级。它只通过该服务的 `LD_LIBRARY_PATH` 加载，不替换 `/lib` 全局库。上游修复来自 [signal watcher 删除后访问修复](https://github.com/openwrt/libubox/commit/a9ab90bd1d5d6cf96051700bce395579264d6c5f) 和 [process watcher 删除后访问修复](https://github.com/openwrt/libubox/commit/c08a4ab5312917e21104fd225136b2ae35e79427)。当前完整私有备份包含已部署文件；公开首页包不自动部署该库。其他机器需重新核对原库、ABI、构建来源与隔离测试。

库缺陷已在隔离程序中复现并修补，修补后真实插件组合三轮通过；**尚不能据此认定此前 rpcd 崩溃的唯一根因**。不要用“这轮没有崩溃”替代根因确认。

## 13.4 每次更新怎样检查

1. **保存基线：** 文件 SHA256、服务 PID、AP、DNS、插件、制式、性能模式和回退文件。
2. **先检查 P0：** SSH、管理网页、热点、DNS、锁/残留进程、资源与内核日志。
3. **审查逻辑：** 不嵌套反向加锁；所有等待有界；失败解除忙状态；取消清理子任务；迟到响应不覆盖新状态。
4. **串行场景测试：** 三轮插件组合、制式往返、性能往返；配合隔离失败注入。真实共享网络测试不得重叠。
5. **恢复并复核：** 回到初始状态，重新确认 DNS、AP、后台及部署校验。保留失败轮次，不覆盖旧证据。
6. **发布与备份：** 公共文件脱敏；设备与公开负载核对；完整私有备份加密、测试归档、核对上传 SHA256。

当前回归摘要见 [2026-10-12 修补与发布验收](reviews/2026-10-12-repair-release.md)。无线 `-12` 的具体命令、真实长期弱信号、此次版本冷启动、完整恢复演练及本轮手机连接均保留为未完成场景；不以普通联网测试替代。

## 13.5 出现问题先做什么

保持 USB 管理和供电，先保存 `/opt/f50-diagnostics/` 对应日期的 `system.log`、`errors.log`、`events.log` 与 `state.log`。记录发生时间、操作目标、是否能关联 Wi-Fi、SSH / LuCI / DNS 哪一层失效，再对照风险编号排查。

日志可能含手机号、域名和网络标识，只保存在本地或私有备份。恢复页面使用第十一章安装时生成的 `restore.sh`；定向修补恢复对应原文件并仅重启受影响服务。整套系统恢复见 [完整备份与换卡恢复](07-backup-and-restore.md)。
